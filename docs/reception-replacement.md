# Resource receptionist runtime

The default web app uses `ReceptionSessionController`, native streaming Gemini Live audio and the `/api/reception` resource API. The server owns session contact, drafts, actual offers, acceptance and durable operation results. The browser carries input/output identifiers, media exposure and HTTP calls; it does not run the old patient-intake or delivery gates.

The default independent database is `data/reception.sqlite`; `RECEPTION_DATABASE_PATH` overrides it. `DATABASE_PATH` remains the legacy backup source. The replacement copies only the fictional bilingual 30-doctor/10-specialty catalog into its own schema. It does not migrate or reset legacy patients, appointments or slots. Token issuance binds the selected server session's prompt/context, current Riyadh clock and saved state.

One accepted presented opening plus valid name/contact prepares an operation. Known synthetic calling metadata needs no dictation; dictated phones require confirmation of their exact canonical version on a later caller turn. Contact corrections preserve unchanged slot acceptance. Explicit household subjects receive independent IDs and approvals while retaining caller contact unless changed. Booking, occupancy, history, result and simulated notification are atomic. Rescheduling preserves appointment ID; failed moves preserve old capacity. Cancellation releases occupancy and records the separate synthetic under-24h classification. Summary links, waitlists, callbacks and transfers are local activity records, with no real delivery or clinical content.

Unexpected transport loss preserves the domain session; recovery fetches authoritative state and reconnects once. Lost commits reconcile the same operation; other lost tool effects retrieve the same event. An admitted unresolved result blocks routine mutations. Emergency pause and explicit Stop establish serialized admission fences and preserve committed results. Farewell requests close only after generated audio drains, and new caller input cancels pending farewell closure.

Run `npm run dev` and open `http://localhost:5173`. Use only fictional contact/name data. `npm test` runs current tests plus retained legacy regression fixtures under `tests/`; rollback archives are excluded. `npm run build` includes TypeScript checks. `npx tsx scripts/smoke-reception.ts --rounds=2` exercises real Arabic Live output with a disposable replacement DB; add `--english` and/or `--dictated` for English and partial-phone repair. Reports and generated WAVs go to `output/reception-live/`. These scripts consume provider usage, but never mutate the persistent demo DB.

The legacy `GeminiLiveSessionController`, tool handler and old booking services remain for explicit legacy tests and historical smoke scripts. Those scripts no longer describe the active web runtime or its token constraints. Old token fixtures inject their own legacy configuration. Do not use old smoke scripts with the replacement token route.

Rollback source/prompt and the consistent SQLite copy are archived at `backups/prototype-2026-10-02T21-12-31-811Z/`. `manifest.json` contains 169 inventoried SHA256 hashes; the database passed SQLite integrity checking. `.env`, dependencies and Git internals are excluded. Restore source into a separate checkout and use the archived `legacy.sqlite`; preserve credentials separately. `scripts/backup-prototype.ts` creates another verified archive without resetting any database.

## Regression migration

| Previous failure | Replacement observable coverage |
| --- | --- |
| Short/repeated/corrected phone; invented digits | `tests/shared/receptionContact.test.ts`, domain contact version and invalid-count tests |
| Generic yes or unheard offer committing | Domain prior-started exposure/onset/subject tests; client carrier and muted-stream tests |
| Duplicate write/lost response/server restart | Domain persistent result/event/rollback tests; adapter same-operation reconciliation and unresolved block |
| Delayed tool after Stop/emergency | Domain both fence linearizations; adapter delayed-snapshot and emergency unknown-reference tests |
| Failed move or cancelled slot still occupied | Domain appointment ID, occupancy and cancellation boundary tests |
| Late captions/replies without replay voice | Client stable output-ID, late partial/final caption and App immutable replay tests |
| Provider interruption/reconnect | Client queue cancellation, media telemetry and bounded recovery tests |

Offline tests prove synthetic state/effect and adapter invariants. Typed Live runs inspect actual transcripts, tool timelines and independent DB results, while saving generated audio for listening. They do not establish microphone recognition, accent naturalness or perceptual voice consistency. Native speech is prompted and can still misstate details; semantic model assertions are not independent proof of hearing or understanding. Current verification results belong in the implementation plan's Verification section.

## Conversation regression repair — 3 October 2026

Microphone captions retain one bounded activity owner through turn completion for trailing fragments when Gemini omits `finished`. Every new caller onset retires that owner, including empty completed turns. Captions update the current activity's stable bubble; orphan fragments receive a separate display-only caption ID and remain visible. Provider captions have no original turn IDs, so cross-onset attribution cannot be proved: current activity is preferred, caption diagnostics are uncertain, and orphan/display IDs never create input or consent activity or change tool-command attribution. Assistant transcription chunks update a single output-ID bubble immediately, with text presentation recorded once and late captions completing the original replay record. Raw transcription diagnostics include local provider event IDs, input/output or display-only caption IDs and final/completion flags without audio or credentials.

Appointment and offer labels are projected on each response/restored snapshot in Asia/Riyadh, including lookup, selection, cached events and recovered durable results. Gregorian, Umm al-Qura and relative labels refresh across local midnight without changing stored UTC times, appointment versions or durable results. The log panel scrolls its own list to the latest entry on each opening and incoming event. Reception guidance accepts a supplied first name, avoids invented surnames/uncertain gender, clarifies who receives help and prompts مُجَمَّع pronunciation without scripted replies.

The earlier coverage used final-marker captions, a single assistant completion callback and same-session lookup; those shapes missed the observed microphone and fresh-session failures. New deterministic regressions exercise missing markers, consecutive/repeated onset, late captions after both completion types, progressive text and one presentation event, stable UI updates, log reopening, fresh-session Saudi lookup and midnight label refresh. New tool/interruption activity distinguishes a new response from a trailing caption on a completed response, while an existing output can continue through tools. `npm test` now passes 607 tests across 52 files; `npm run build` passes. Use `npx tsx scripts/smoke-reception.ts --regressions --rounds=1` (add `--english`) for a first-name-only booking at 9 AM Riyadh and lookup from a distinct fresh session in a disposable database. The scenario checks stored name/time, spoken Saudi time, unchanged lookup storage and the current session's farewell fence. Test-only spoken-time assertions are not runtime output gates. Typed generated-audio runs still cannot establish microphone ASR, audible accent or pronunciation quality.

Review corrections add three controller regressions for trailing input captions after turnComplete, an empty completed turn followed by a new real caption, and bounded orphan captions without manufactured consent.
